## 1. 這是什麼

一個 **MCP server**，把「生成」與「判斷」拆開。Jev（TypeSafe 的 non-autoregressive
decision model）只做 typed 判斷，deterministic code 負責 schema、授權、門檻、組合、
fail-closed。

- Repo：`/Users/you/dev/jev-gate-mcp`
- Branch：`main`／Remote：`https://github.com/royalskynet/jev-gate-mcp.git`
- 執行形態：**stdio MCP plugin，唯一主路徑**。HTTP / Docker / Caddy 整層已於 2026-09-21 刪除，不要復活。
- Provider：OpenRouter，`https://openrouter.ai/api/v1/systemone`，model `typesafe/jev-1.13`
  （回應的 `model` 欄為 `typesafe/jev-1.13-20260917`）
- Provider token 放在檔案，路徑寫在 `hooks/jev.js` 的 `CONFIG.apiKeyFile`。
  **只讀路徑，永遠不要把值讀進 stdout／log／commit／報告。**

### MCP surface：只有兩支工具，不准加第三支

| 工具 | 用途 | 規則擁有者 |
|---|---|---|
| `jev_evaluate` | 一次性、窄範圍的 Choice／Score／Noul 判斷 | caller |
| `jev_apply_policy` | 伺服器自有、帶版本的 policy，回 `accept`/`review`/`escalate`/`deny` | 伺服器 |

**兩支都是 advisory。**「MCP 有這個工具」不等於「規則被執行」——真正的阻斷要 host 端
實作，契約見 [`docs/host-adapter.md`](host-adapter.md)。

## 5. 開放問題（沒做，有理由，不要當成漏做）

### 5.1 跨 policy 沒有批次〔效能缺口，已知形狀〕

adapter 簽名本來就收複數 `questions`，所以**單一 policy 內已經是批次**。
但連續套五個 policy 就是五次往返。

卡點不是懶：每個 policy 宣告自己的 `state_projection`，五份投影互不相同。要合併成
一次呼叫，得先回答「怎麼送五份不同投影的 state，而且不讓 A policy 的欄位漏進 B 的題目」。
硬合併等於拆掉 state_projection 這道隔離牆換效能。

**前置條件：先有標註集能證明合併後答案沒變差。** 在那之前不要動。

### 5.2 laya 評估〔外部替代方案，已查證，結論是並存不取代〕

<https://github.com/NandhaKishorM/laya> — Apache-2.0、Python、2026-09-18 建、v0.3.4 beta、
單人維護。原語完全相同（`choice`/`score`/`noul`），questions schema 幾乎一樣，
理論上是 adapter 級可換。

**實測數字（在這台 M4 / 24 GB 上量的）：**

```
venv 總計 494 MB（torch 339 MB、transformers 54 MB、sympy 29 MB、numpy 20 MB）
torch 2.8.0 / transformers 4.57.6 / arm64
mps_built True  mps_avail False      ← 沒有 GPU 路徑
磁碟可用 22 Gi / 總 228 Gi
```

權重（**估算，未實測**——`huggingface.co` 不在沙箱允許清單）：程式碼在 CPU/MPS 強制
`torch.float32`（`agent.py:201`），所以 RAM = 參數 × 4 bytes：`laya` 421M ≈ 1.7 GB、
`laya-multilingual` 322M ≈ 1.3 GB、`laya-typed-decisions` 421M ≈ 1.7 GB。
`Router(preload=True)` 三個全常駐 ≈ **5 GB 磁碟 + 5 GB RAM**。

**三個硬事實：**

1. **context 只有 512（英文）／1024（多語）token。** `hooks/jev.js` 的
   `chunkChars: 16000` ≈ 4000 token，**塞不進去**。要用得重做分塊策略。
2. **本機 CPU 反而比較慢。** laya CPU 193–464 ms／次；hook 現在用 `Promise.all`
   **併發**判 8 個 chunk（`hooks/jev.js:135`），牆鐘 ≈ 一次往返 250–500 ms。
   改 laya 會變成 1.5–3 秒（torch CPU 已吃滿核，併發只會互搶）。
3. **省的錢很小。** Jev $0.042/1M token；單次重工具呼叫 8 chunk ≈ 32k token ≈ $0.0013，
   一天 500 次也才 $0.67。**上限 $20／月。**

**結論：熱路徑留 Jev，離線路徑用 laya。** laya 真正值錢的不是省錢，是
（a）state 不用外送——我們 telemetry 都做成 allowlist 了，卻還是把投影後 state 送出去，
這矛盾一直在；（b）免費才敢大量收標註集，正好打通 §4 那個瓶頸。

下一步若要做：寫 `makeLayaAdapter`（Python sidecar），**只接離線標註集路徑**，
拿同一批標註集用 `calibrate.mjs` 比 Jev vs laya 的 precision/recall/ECE。

打折提醒：他們 README 的 Jev 對照欄是**第三方公布、非自測**（自己寫了
"never measured here"）；宣稱的 ECE 0.081 是 **temperature fitting 之後**，
raw ECE 0.213 其實輸給 Jev 的 0.144。

### 5.3 prune hook 的 ledger 空白〔已查明，修的是 observability〕

```sh
$ wc -l /Users/you/.openclaw/state/jev-prune.log
→ No such file or directory   #（接手時）
```

**根因**（用真實 `tool.call` 證據分層判定，非猜 threshold）：

- hook **有載入**：`~/.claude/debug/` 的 probe session 有
  `hooks module jev-gate@jev-gate loaded ... events: tool.call` 與
  `jev-gate@jev-gate tool.call settled in 1746.0ms`（= 跑了真實 provider 判斷）。
- wire **會 drop**：同一 noisy fixture 用真 provider 走 `pruneText+judgeChunk`，
  `35942 → 16043 chars, 223 lines dropped`。
- 真 host 上整條 `prune→ledger` 可寫：完整 `$`（`clock.now`+`fs.write`）下寫進
  `jev-prune.log` 一筆 `... jev-prune(Bash): 44042 → 16027 chars, 573 lines dropped`。
- 但原本 ledger **只在 `droppedLines > 0` 時寫**、且寫失敗被 swallow-all catch 吞掉，
  所以「hook 觸發、judge 全回 keep」的狀態零痕跡（probe 的 diag 量到過
  `out=7999 kept=7999 dropped=0`）。§5.3 的「沒查」正是卡在：沒有 drop 就沒有任何
  可寫的記錄。

**修（只動 observability，不碰 policy/threshold/校準）**：`hooks/jev.js` 抽出
`appendLedger()`，每個被判定過的超門檻呼叫（keep 或 drop）都寫一行 ledger；ledger
失敗不再弄壞 prune（still never throws）。`tests/hook.live.test.js` 補 regression：
`appendLedger` 寫 ISO 行、ledger 失敗不 throw、活線 drop 會寫 ledger 行。測試數
105 → 108（+3）。

注意別跟舊路徑搞混：`plugin/hooks/prune.js` 是**已停用的舊實作**，
`docs/NEXT.md` 裡 `59889 → 119` 那個驗證講的是舊的那支。**單次 drop 不是品質校準**——
ledger 有筆 ≠ 判準已校準，`calibration_status` 仍 `uncalibrated`。

|---|---|
| route accuracy / no_match | 命中候選比例；無匹配是否回 `no_match` |
| compaction reduction + rerun | 每 pass 減的 chars；不足最小 reduction 的回退次數 |
| verify false-pass / unknown | pass 但證據不足的比例；`unknown` 只在真缺證據 |
| review precision / latency | 真 diff 吃進的精確度；端到端延遲 |

**邊界（不可跨越）**：五個 policy 維持 `shadow` + `uncalibrated` + rollout 0
（`tests/agent-glue/policy-shadow.test.js` 是防回歸守門）。Jev 結果只在膠水層當
advisory／ledger，**永不**改動 deterministic severity／reviewer route，**永不**硬阻擋或授權。
驗收：`npm run agents:acceptance`。
